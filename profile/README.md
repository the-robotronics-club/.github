## About

The **Robotronics Club** is the robotics and autonomous systems engineering group of the **Indian Institute of Technology Mandi**. We design, build, and research robotic systems spanning embedded electronics, computer vision, artificial intelligence, aerial robotics, and mobile robotics — with an emphasis on open, reproducible engineering.

## What We Do

**Autonomous Robotics** — Navigation, localization, SLAM, path planning, and obstacle avoidance for ground and aerial platforms.

**Embedded Systems** — Microcontroller firmware, sensor integration, motor control, communication protocols, and real-time systems.

**Computer Vision** — Object detection, tracking, visual odometry, depth perception, and perception pipelines.

**AI & Machine Learning** — Robotics-oriented learning systems, reinforcement learning, and intelligent decision-making.

**UAV / Aerial Robotics** — Flight controllers, telemetry, autonomous navigation, and aerial perception.

**ROS / ROS 2** — Middleware, simulation, navigation stacks, and distributed robotic control.

**Mechanical & Mechatronics** — CAD, mechanism design, drivetrains, fabrication, and electromechanical integration.

---

## Research & Development

The club is not purely competition-oriented. Ongoing work spans experimental robotics, control theory, embedded intelligence, simulation, human-robot interaction, multi-robot coordination, and field robotics. Members are encouraged to document findings as open, reproducible engineering artifacts rather than one-off competition code.

## Open Source Standards

Repositories under this organization are expected to include, where applicable:

- A clear, complete README
- Installation instructions
- Hardware requirements (where relevant)
- Software dependencies
- Architecture or system diagrams
- Usage instructions and examples
- Contribution guidelines
- An explicit license
- An active issue tracker

Documenting engineering work is treated as part of the work itself, not an afterthought.

---

## Contributing

1. Fork the repository.
2. Create a feature branch.
3. Implement and test your changes.
4. Commit with a clear, conventional message.
5. Push your branch.
6. Open a pull request.

```bash
git clone https://github.com/Robotronics-Club/<repository>.git
cd <repository>

git checkout -b feature/my-feature

git add .
git commit -m "feat: add my feature"

git push origin feature/my-feature
```

Contribution requirements can vary by repository. Where present, refer to that repository's `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, and issue tracker for specifics.

---

## Engineering Standards

- Write readable, maintainable code
- Use meaningful, conventional commit messages
- Practice issue-driven development
- Document architecture and reasoning, not just usage
- Prioritize reproducibility across hardware and software versions
- Test before merging; review before shipping
- Disclose and review AI-generated code rather than merging it blindly
- Attribute external code, libraries, and datasets properly
- License all published work explicitly

## Statistics Methodology

- **Scope:** Public, non-archived repositories owned directly by this organization, unless the workflow is reconfigured otherwise.
- **Update cadence:** Once per day via scheduled GitHub Actions run, plus on manual dispatch and on pushes to the stats workflow itself.
- **Not included by default:** Private repositories, forks (counted separately if enabled), and archived repositories.
- **Source:** `scripts/generate_org_stats.py`, executed by `.github/workflows/update-org-stats.yml`.

This distinction matters: nothing on this page is claimed to be "live" unless it is served directly by an external badge/API at render time (see the Shields.io badges above). Everything else is periodically generated and committed.
